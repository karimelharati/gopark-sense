# GoPark Sense - local hackathon app

## Run on another Windows laptop

The project can run from any normal folder on another Windows 10/11 x64 laptop. You do not need the original computer, its folders, its shortcuts, its database, or Codex.

1. Install [Node.js](https://nodejs.org/en/download), version 22.13 or newer, with npm. Chrome or Microsoft Edge is needed for the app windows.
2. Download this repository with **Code -> Download ZIP**, then **extract the ZIP**. Alternatively, clone it with GitHub Desktop.
3. Inside the extracted project folder, double-click **SETUP.cmd**. Keep internet access on while dependencies and the official Cloudflare helper are downloaded. Setup builds the app and prepares this laptop's local database. If setup reports an error, follow it and rerun; existing bookings are preserved.
4. Double-click **Open GoPark.cmd** for the main app. It opens at http://127.0.0.1:4173.
5. For the live two-phone demo, double-click **Open GoPark Two Phones.cmd**. Scan its attendant QR on one phone and its driver QR on the other. Enable precise location on both phones and keep their screens open. New tests use a 10 m estimated alert distance, adjustable by the attendant. Keep this laptop awake and online.

**Stop GoPark.cmd** stops the main app. **Stop GoPark Two Phones.cmd** stops the phone server and its temporary HTTPS link. The regular app works locally; phones use a temporary HTTPS tunnel so browser location permissions work. Another laptop starts with its own demo data and creates its own phone links; the original laptop does not need to be running.

The first setup takes longer while packages download and the app builds. Running setup again does not replace the existing parking database. Helper binaries and all runtime data stay in ignored local folders and are not uploaded to GitHub. Gate movement, payments, and rewards remain simulations.

## What is implemented

- Driver-assisted gate, attendant-operated gate, and attendant without gate. Select a location under **Gate console → Setup & privacy**.
- GPS proximity, driver presence requests, attendant arrival notifications, upcoming arrivals/departures, missed check-ins, overstays, and unconfirmed movements. Desktop notifications are optional; foreground in-app alerts remain available.
- Camera/photo plate OCR with manual review. Gate requests, authorization, opening, and actual vehicle crossings are separate events. Opening a gate or moving a phone never releases capacity.
- Scheduled bookings and interval-wide capacity checks. Current physical occupancy, current reservation holds, and future availability are distinct. Shared-pool walk-ins are counted; unknown observed arrivals remain visible and provisional.
- Driver star ratings, recoverable perks, tier discounts, priority queues, rooftop access, loyalty points, ten-point rewards and free-hour coupons from the earlier version.
- Pre-start cancellation with a displayed refund preview; duration changes; no-show expiry; simulated overstay fees; verified displacement refunds and compensation; consented replacement parking and voluntary relocation.
- Audit search by plate/booking/driver, timestamp corrections, disputes, refund adjustments and penalty reversals with retained history.
- Signed offline booking receipts, device-signed rotating QR proofs, image/camera verification, local replay checks, provisional offline occupancy and an observation outbox. Synchronization is idempotent and retains observed and received times.
- A seeded discrete-event simulation with editable assumptions, comparison charts and JSON export. CLI reports are generated by `node scripts/simulate.mjs 42` into `outputs/evaluation/`.
- Paired-token hardware API, an explicit opt-in hardware-only LAN bridge, ESP32 tabletop firmware and wiring/cost guidance in `hardware/`.

**Early-leave credit is intentionally not implemented.** A normally completed on-time visit can earn its usual points; leaving early does not earn an additional unused-time credit or automatic refund.

## Default policies

Refund = paid booking amount × `min(1, minutes before start / 120)`. Cancellation is eligible only before the scheduled start and before check-in. The 120-minute full-refund notice is configurable. The previous arrival-plus-30 cancellation rule has been replaced by this newer policy.

Arrival is allowed from 15 minutes before start to 30 minutes afterward. Unused no-show holds expire after 30 minutes, without inferring that a vehicle left. Real observed vehicles remain in occupancy until an observed departure or recorded reconciliation.

On-time completed visits earn 2 loyalty points and 5 tier score. Every 10 loyalty points can be exchanged for a demo reward. Stars recover by 0.05 per on-time visit. Spending points does not reduce rating or tier.

Overstay grace is 10 minutes. Each started 15-minute block beyond grace adds 2 penalty points, removes 4 tier score and charges 150% of the normal hourly rate for that block. More than 60 minutes late adds 25 further tier-score loss. Verified disruption adds a $5 simulated fee, 4 penalty points and a stronger rating/tier deduction. All amounts and scores are configurable. Penalties settle once at confirmed departure.

Verified displaced drivers receive a full simulated refund and 5 compensation points independently of collecting the blocker’s fee. Alternatives are capacity-checked and require consent. Replacement price is 80% of the lower of the comparable normal price and original booking amount; free originals remain free. Relocation is charged at its normal displayed tier rate and does not release the original space before departure.

The less convenient Hamra location requires acceptance before booking and gives 2 bonus points after an eligible completed stay. It does not award points simply for accepting and cancelling.

Before-start duration reductions can adjust the simulated price. Reductions after check-in do not issue early-leave credit. Extensions must be requested before expiry and cannot overlap committed capacity.

## Suggested demonstration

**Live two-phone test (no fixed destination):** double-click **Open GoPark Two Phones.cmd** in the project folder after completing **SETUP.cmd**. The laptop pairing window shows two QR codes. Scan **Test attendant** with phone 1 and **Test driver** with phone 2. Tap **Enable live location** on both phones and grant precise location. These codes pair the phones once; there is no arrival scan or driver confirmation. Keep both screens open and the laptop awake with internet access.

Move either phone toward the other, anywhere. The attendant receives an in-app arrival popup when both fresh estimated GPS positions are within the selected distance. New tests default to 10 metres; choices range from 10-300 metres. Existing sessions keep their previous setting until changed. The popup labels uncertain matches and requires the attendant to identify the car. A 10 m setting does not guarantee 10 m physical accuracy. Test outdoors. There is no fixed parking coordinate; if the phones start close, the alert appears as soon as both provide suitable fixes.

The attendant identifies the displayed car and taps **Confirm car & open gate**. Both phones show the simulated gate opening. Occupancy stays at zero until the attendant taps **Car has entered**, then becomes one. **Confirm car has departed** frees the space. **Reset test** starts another visit without pairing again. Pause the driver's GPS, move outside the alert distance, reset, and enable GPS again to repeat the approach. Pausing either phone immediately prevents a proximity-based opening until fresh nearby positions return. The arrival popup stays visible during a temporary loss of location, with its open control disabled. Staff can dismiss it with Review on dashboard, or use Show arrival popup again. Both phones show the same session code plus separate driver and attendant location freshness/accuracy diagnostics. GPS going away never releases a parked car's space.

The laptop starts an isolated companion server on loopback port 4175. An official Cloudflare Quick Tunnel supplies temporary HTTPS so browser GPS works on phones using Wi-Fi or mobile data. A restart can change the address: reopen pairing and scan the current codes. Double-click **Stop GoPark Two Phones.cmd** to close access. Driver and attendant links have separate server-enforced permissions; keep them private. Laptop setup and regular GoPark data routes are unavailable through the temporary link. Precise coordinates stay in memory and are not saved in the room database; role-key hashes, visit events, and simulated inventory are saved. Sessions expire after eight hours.

This is a foreground browser test with simulated gate movement and separate demo capacity. It does not control a physical gate or provide background push alerts while the phone is locked. Chrome/Safari can add the paired page to the home screen. Automated verification uses independent mobile browser contexts over the actual HTTPS link and emulated GPS; a physical phone field test is still needed. The design follows the [browser geolocation permission and secure-context requirements](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API) and uses [Cloudflare Quick Tunnels for temporary testing](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

**Destination parking:** in **Find parking**, enter where you are going, set arrival and duration, then choose **Find closest parking**. Enter a place/address in Lebanon, a `latitude, longitude` pair, or use a labeled demo destination. Ambiguous place searches ask you to choose the intended place. Recommendations exclude full intervals, restricted tiers and immediate priority-queue conflicts, then sort remaining GoPark lots within 5 km by straight-line distance to the destination. Reserve the recommended lot or an alternative; the searched time and duration carry into the booking form. Less convenient locations still require acceptance. Walking routes open separately in Google Maps; proximity ranking is not a routed walking-distance calculation.

Free-form place lookup uses [Photon](https://github.com/komoot/photon/blob/master/docs/api-v1.md) over OpenStreetMap data. Requests run only on explicit submission, with caching, a conservative rate limit, timeout and an error fallback. Built-in approximate demo landmarks and manually entered coordinates do not need online place lookup. The public Photon demonstration service has no availability guarantee; configure the trusted server environment variable `PHOTON_SEARCH_URL` to use another compatible HTTPS instance. Search text is not saved in the parking database. No Nominatim public API is used.

**Animated arrival:** run **Open GoPark.cmd --arrival-demo**, open **Gate console → Visual demo**, or run `Open GoPark.cmd --arrival-demo`. Choose one of four cases: **1. Gate + driver confirmation; 2. Gate + automatic GPS alert; 3. No gate + driver confirmation; 4. No gate + automatic GPS alert.** Cases 1 and 3 require the driver to tap **Confirm my arrival**. Cases 2 and 4 have no driver buttons. In gated cases, the attendant opens the gate and passage confirms check-in. In ungated cases, the car enters without a barrier and the attendant confirms its actual entry before occupancy updates. **Play full demo** animates every actor’s steps; **Try this case** pauses for the required driver or attendant action. Selecting a different case resets the visual scenario. The eight-space lane is simulated and does not alter saved bookings or open a physical gate.

1. Explore → reserve an AUB space starting in 15 minutes. Review the interval, cancellation terms and tier discount.
2. My parking → enable GPS, then “I’m at the entrance.” The attendant receives an alert; occupancy remains unchanged.
3. Gate console → authorize if required → simulate gate opening. Occupancy still remains unchanged. Confirm staff-observed or simulated passage to check in.
4. Save/open the offline pass. Open **Offline attendant tools** before disconnecting to cache its shell and trusted issuer information.
5. Verify the rotating code, identify the vehicle and record an actual entry/exit offline. The local estimate is explicitly provisional. Reconnect and synchronize; repeat synchronization to demonstrate no duplicate visit or reward.
6. Recovery → **Create isolated overstay scenario**. This adds a separate one-space lane and two sample drivers without resetting existing bookings. Verify the cause, refund the displaced driver, then review and accept a nearby replacement as that driver.
7. Simulation → run a fixed seed and export parameters/results. Compare admissions and rejected/rerouted requests as well as accuracy and conflicts.
8. Audit & disputes → search the booking, correct an observed timestamp or resolve an adjustment with a reason.

## Offline pass guarantees and limitations

The server signs a booking certificate using an issuer key stored only in the local database. A non-exportable device key held in IndexedDB signs a fresh 30-second possession proof. Compressed Base45 QR transport makes it readable at phone sizes. The attendant verifies both signatures against the previously cached issuer key.

A fresh rotating QR is not proof of vehicle passage and does not eliminate screenshots within the acceptance window. Replay checks are local to each verifier. A cached cancellation manifest can be stale, so offline movements remain provisional until reconciliation. A known cancellation, changed version, expired proof, wrong issuer or wrong device signature is rejected. Unknown or conflicting records go to review rather than silently charging or blaming a driver.

The offline wallet caches its generic HTML/JS/CSS shell. Private receipts, the public trust manifest, the snapshot and pending observations are stored explicitly in IndexedDB. Raw camera images are not uploaded. Device cache clearing is blocked while observations are pending.

## Hardware

See `hardware/README.md`. Default startup is loopback-only. `Open GoPark.cmd --lan` opts into a **hardware-only bridge on port 4174**; it forwards only the paired-token `/api/hardware` route to the loopback app. The driver/staff interface remains on port 4173.

Firmware uses a low-voltage LED/relay pulse and two direction-sensitive beam inputs. The device must be paired and configured before use. No real barrier or board was connected or compiled in this workspace. A two-beam tabletop model is not a production tailgating/identity system. Reuse suitable installed hardware where possible; supplier prices, installation and recurring costs need measuring separately.

## Run from source

The Windows SETUP.cmd wrapper is the simplest option. With Node.js 22.13+ and npm installed, terminal users can run:

```powershell
npm.cmd run setup
npm.cmd run desktop
```

Run the two-phone demo separately with `npm.cmd run phones`. The laptop pairing screen provides the current phone links. Internet is required for the temporary HTTPS tunnel; screens must remain open for location and arrival popups.

Setup installs missing dependencies, builds the project, creates the three current database tables if absent, and finds or downloads the official Cloudflare helper. Downloaded Windows binaries are checked against the SHA-256 digest from the official release metadata. Setup checks an existing portable helper, a project-local copy in .sites-runtime/tools, and PATH. GOPARK_CLOUDFLARED can specify an installed helper's full path. Nothing is installed system-wide. Run `npm.cmd run setup -- --reinstall` if dependencies are incomplete.

The double-click launchers and automatic helper download target Windows x64. On other operating systems, install a suitable cloudflared helper on PATH and use the source commands; desktop launch and physical phone behavior on that system have not been verified. On macOS/Linux use `npm` instead of `npm.cmd`.

To build without setup, use `npm.cmd run install:ci` and `npm.cmd run build`. A fresh main-app database must then be initialized with the SQL files under drizzle before starting Wrangler. Prefer setup: it applies the current table definitions idempotently and preserves saved data. Local runtime data, signing keys, pairing tokens, build output and dependencies are excluded by .gitignore.

## Verification and practical limits

```powershell
node --test tests/parking.test.mjs tests/workflows.test.mjs tests/passes.test.mjs
node node_modules/typescript/bin/tsc --noEmit
node scripts/simulate.mjs 42
```

Simulation results are synthetic and assumption-dependent, not measured production accuracy. The model offers the same generated demand to both policies, but can admit different requests. Rejections/rerouting and recovery effort must be considered alongside occupancy accuracy.

All payments, refunds, merchant offers and normal gate-opening controls are simulated. GPS is foreground browser assistance and needs permission; plate OCR needs its recognition model on first use. Sample-driver switching is a private single-operator demo, not production driver/staff authentication. Real deployment needs authenticated roles, a complete vehicle feed, validated local plates, reliable gate sensing, payment integration, merchant agreements and field testing.
